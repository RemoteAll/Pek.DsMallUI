# Pek.DsMallUI 迁移说明（C# → Rust，2026-11-09）

> 依据：C# 参考工程 `G:\Code\Pek.FrameWork\Pek.DsMallUI\Pek.DsMallUI` 全部源码文件（含 `wwwroot` 资产体量），
> 逐文件判定「可移植 / 改写 / 不适用 / 待办」，并与本 crate `src/**` 实际实现比对。
> 文件级逐项映射见 `docs/移植对照.md`；本文给**结论与缺口台账**。

## 一、结论

**可移植部分已全部落地**：UEditor 后端（配置/上传/涂鸦/远程抓取/文件列表/路径格式化）、
上传下载控制器、后台 Area（站点设置 / 登录）、Razor 子集视图、折叠实体、静态资源服务。
**架构性不可移植**（依赖 XCode/NuGet/ASP.NET 宿主）的部分不迁，改为 `AdminBackend` 抽象与
`dhrust` 现有能力；**真实缺口只剩 2 项**（G1 站点地图定时任务、G2 多语言设置）——
G3 图床直传、G4 Word 转 HTML 在 C# 侧本身就是注释状态，不计为缺口，详见第三节。

## 四、架构性不适用（不计为缺口）

| C# | 原因 | Rust 侧等价做法 |

| `PekStartup.ConfigureServices` 里对 `Role`/`Department`/`User` 的初始化 | 依赖 XCode 实体与数据库 schema | 由消费方在启动时自己初始化；本 crate 不碰业务表 |

| `Common/PekHtmlExtensions.cs` | 依赖 XCode `FieldItem` + NewLife `HtmlHelper` 扩展 | 表单直接写在 Razor 子集视图里 |

## 五、迁移口径（与 C# 的差异，均已修正并留痕）

1. **上传真的会落盘**：C# `UploadHandler.Process` 与 `Crawler.Fetch` 是注释状态（上传永远「未知错误」）；
   Rust 按 UEditor 官方协议实现。
2. **`{rand:n}` 位数**：C# 实际 n+1 位 → Rust 按官方 n 位。
3. **文件名清洗**：C# 删除非法字符；Rust 用 `dhrust::io::sanitize_file_name`（→`_`、`..`→`__`）+ 落盘越界校验。
4. **抓图 SSRF**：C# 校验被注释 → Rust 只允许 `http`/`https`。
5. **扩展名白名单**：C# `GetStringList` 恒返回空（任何上传必被拒）→ Rust 正常读配置并归一化（`webp` 补点）。
6. **持久化/口令**：C# 直写 XCode + `SaltPasswordProvider`；Rust 用 `AdminBackend` + `dhrust::sign::password`（字节级互通）。
7. **UEditor 兜底与缺省 action**（2026-11-09 复核补登）：C# 未带 `action` 与未知 `action` 都走
   `NotSupportedHandler`（`action 参数为空或者 action 不被支持。`）；Rust 未带 `action` 时按 UEditor 惯例回
   **config**，未知 `action` 回 `不支持的操作：{action}`。消费方若依赖 C# 文案需自行适配。
8. **下载缺失文件**：C# `Download` 找不到文件返回 `200` + 正文 `null`；Rust 返回 `404 Not Found`
   （语义更正确，前端若以 `null` 判空需改为按状态码判断）。
9. **能力超集**：C# 的 `uploadvideo` / `listimage` / `listfile` 均在注释里（未启用），Rust 正常实现。
